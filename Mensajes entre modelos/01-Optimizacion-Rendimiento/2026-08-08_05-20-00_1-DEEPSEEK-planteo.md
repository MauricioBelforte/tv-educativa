## 3. HITOS A IMPLEMENTAR (en orden de prioridad)

### H5 — React.memo en ChannelCard (PRIORIDAD MÁXIMA, hacer primero)

**Archivo:** `src/components/ChannelCard.tsx`

**Problema:** Cada vez que cambia cualquier estado del store (ej: `channelStatus` de un canal), TODAS las ChannelCard se re-renderizan porque no están memoizadas. Con 500+ canales, esto es un cuello de botella enorme.

**Solución:**
1. Envolver el componente con `React.memo`:
   ```tsx
   const ChannelCard = memo(function ChannelCard({ channel, listId: propListId, allCategories = [] }: ChannelCardProps) {
     // ...código existente sin cambios...
   })
   export default ChannelCard
   ```
2. **CRÍTICO:** El componente usa selectores de Zustand individuales (`usePlayerStore((state) => state.X)`). Esto ya es correcto — cada selector solo re-renderiza cuando esa porción cambia. El `memo` evita re-render por cambios en props del padre.
3. **Problema a resolver:** `ownerList` se calcula con `importedLists.find(...)` en cada render. Con `memo`, esto solo se ejecuta cuando cambian las props (`channel`, `listId`, `allCategories`). **PERO** `importedLists` es un selector del store, así que si cambia, el componente se re-renderiza igual. Esto es aceptable porque `importedLists` solo cambia al agregar/quitar listas.
4. **Optimización adicional dentro del componente:** El cálculo `const ownerList = importedLists.find(l => l.channels.some(c => c.id === channel.id))` es O(n*m) por card. Con `memo` se amortiza, pero si querés ir más lejos, se puede pasar `listId` como prop desde el padre (ChannelList ya recibe `listId`). **Recomendación:** pasar `listId={listId}` en ChannelList.tsx línea 122 (`<ChannelCard channel={channel} />` → `<ChannelCard channel={channel} listId={listId} />`) para evitar el `.find()` costoso. Mantener el fallback `ownerList` solo si `propListId` no viene.

**Criterio de éxito:** Al hacer clic en "favorito" de un canal, solo esa card se re-renderiza (verificable con React DevTools Profiler).

### H1 — Virtualización de lista (PRIORIDAD ALTA)

**Archivo:** `src/components/ChannelList.tsx`

**Problema:** Renderiza TODOS los canales filtrados en el DOM. Con 500+ canales, el DOM tiene 500+ nodos complejos (imágenes, botones, menús).

**Solución — Virtualización manual SIN dependencias nuevas** (evitar `react-window` para no agregar deps):

1. Agregar estado de scroll:
   ```tsx
   const [scrollTop, setScrollTop] = useState(0)
   const [viewportHeight, setViewportHeight] = useState(0)
   ```
2. Medir el contenedor con `ResizeObserver` (o `useEffect` + `clientHeight`).
3. Calcular el rango visible:
   ```tsx
   const ROW_HEIGHT = 68 // altura aproximada de cada card (p-3 + logo 48px + gap)
   const OVERSCAN = 5 // canales extra arriba/abajo para scroll suave
   const startIndex = Math.max(0, Math.floor(scrollTop / ROW_HEIGHT) - OVERSCAN)
   const endIndex = Math.min(channels.length, Math.ceil((scrollTop + viewportHeight) / ROW_HEIGHT) + OVERSCAN)
   const visibleChannels = channels.slice(startIndex, endIndex)
   ```
4. Renderizar solo `visibleChannels` con un `paddingTop` y `paddingBottom` para mantener el scroll:
   ```tsx
   <div
     ref={listRef}
     onScroll={(e) => setScrollTop(e.currentTarget.scrollTop)}
     className="space-y-1 select-none overflow-y-auto"
     style={{ height: '100%' }}
   >
     <div style={{ paddingTop: startIndex * ROW_HEIGHT, paddingBottom: (channels.length - endIndex) * ROW_HEIGHT }}>
       {visibleChannels.map((channel, i) => {
         const index = startIndex + i
         // ...mismo código de drag & drop usando `index` real...
       })}
     </div>
   </div>
   ```
5. **IMPORTANTE — Drag & drop:** Los handlers `handleDragStart`, `handleDragOver`, `handleDrop` usan `index`. Con virtualización, `index` debe ser el índice REAL en `channels` (no el índice en `visibleChannels`). El código de ejemplo ya lo maneja con `const index = startIndex + i`.
6. **IMPORTANTE — scrollIntoView:** El `useEffect` que hace `scrollIntoView` al cambiar `currentChannelId` debe seguir funcionando. Como el elemento puede no estar montado si está fuera del rango visible, hay que scrollar el contenedor manualmente:
   ```tsx
   useEffect(() => {
     if (!currentChannelId) return
     const idx = channels.findIndex(c => c.id === currentChannelId)
     if (idx === -1) return
     const targetTop = idx * ROW_HEIGHT
     const currentTop = listRef.current?.scrollTop ?? 0
     const currentBottom = currentTop + (listRef.current?.clientHeight ?? 0)
     if (targetTop < currentTop || targetTop > currentBottom - ROW_HEIGHT) {
       listRef.current?.scrollTo({ top: targetTop - (listRef.current?.clientHeight ?? 0) / 2 + ROW_HEIGHT / 2, behavior: 'smooth' })
     }
   }, [currentChannelId, channels])
   ```
7. **Skeleton de carga:** Mantener el bloque `if (isLoading)` tal cual (no virtualizar skeletons).
8. **Estado vacío:** Mantener el bloque `if (channels.length === 0)` tal cual.

**Criterio de éxito:** Con 500+ canales, el DOM tiene ~20 nodos de cards en vez de 500+. Scroll suave sin saltos.

### H3 — Debounce en búsqueda (PRIORIDAD ALTA)

**Archivos:** `src/app/page.tsx` (principal) y opcionalmente `src/components/SearchBar.tsx`

**Problema:** `onSearchChange={setSearchQuery}` re-renderiza TODO el árbol (Header, ChannelList, filtros) en CADA tecla. Con 500+ canales, cada tecla dispara filtrado + re-render masivo.

**Solución — Debounce en page.tsx:**

1. Agregar estado intermedio y debounce:
   ```tsx
   const [searchInput, setSearchInput] = useState('')
   const [searchQuery, setSearchQuery] = useState('')
   
   useEffect(() => {
     const timer = setTimeout(() => setSearchQuery(searchInput), 300)
     return () => clearTimeout(timer)
   }, [searchInput])
   ```
2. Cambiar `<Header searchQuery={searchQuery} onSearchChange={setSearchQuery} />` → `<Header searchQuery={searchInput} onSearchChange={setSearchInput} />`
3. **OJO:** `searchQuery` (el debounced) se usa en `currentSourceName`, `displayChannels`, `filteredChannels`, `activeCategories`. `searchInput` (el inmediato) se usa solo para el input visual. Esto da feedback instantáneo al usuario (el texto aparece) pero el filtrado pesado espera 300ms.
4. **OJO con el botón de limpiar:** SearchBar tiene un botón "X" que llama `onChange('')`. Con debounce, al limpiar hay que resetear AMBOS estados. La forma más simple: en el `onSearchChange` de page, si el valor es `''`, setear ambos inmediatamente:
   ```tsx
   const handleSearchChange = (value: string) => {
     setSearchInput(value)
     if (value === '') setSearchQuery('')
   }
   ```

**Criterio de éxito:** Escribir "tele" en el buscador no congela la UI. El filtrado ocurre 300ms después de dejar de escribir.

### H4 — Selectores granulares en Player (PRIORIDAD MEDIA)

**Archivo:** `src/components/Player.tsx`

**Problema:** El Player ya usa selectores individuales (`currentChannel`, `isPlaying`, `togglePlay`, `detectedStreams`). **Esto ya está bien.** La única mejora posible:

1. **`detectedStreams` es un objeto que cambia entero** cuando se agrega/elimina un stream detectado. El Player se re-renderiza aunque el stream detectado sea de OTRO canal. Solución: selector que devuelva solo el stream del canal actual:
   ```tsx
   const currentChannel = usePlayerStore((state) => state.currentChannel)
   const detectedUrl = usePlayerStore((state) => 
     state.currentChannel ? state.detectedStreams[state.currentChannel.id] : null
   )
   ```
   Esto requiere mover el cálculo `detectedUrl` ANTES de los hooks (no puede ir después de un early return). Reestructurar:
   ```tsx
   const currentChannel = usePlayerStore((state) => state.currentChannel)
   const detectedUrl = usePlayerStore((state) => 
     state.currentChannel ? state.detectedStreams[state.currentChannel.id] : null
   )
   const isPlaying = usePlayerStore((state) => state.isPlaying)
   const togglePlay = usePlayerStore((state) => state.togglePlay)
   ```
   Y eliminar la línea `const detectedUrl = currentChannel ? detectedStreams[currentChannel.id] : null` (línea 32) y el selector `detectedStreams` (línea 23).

2. **`isLoading` y `error` son estado local** — ya están bien.

**Criterio de éxito:** Detectar el stream de un canal no re-renderiza el Player si el canal actual no cambió.

     const importedChannels = parseM3U(m3uContent)

Esto es correcto (hay que re-filtrar), pero considerá que durante `fastRecheckAllChannels` (concurrencia 20) el `channelStatus` cambia 20 veces por segundo → 20 re-filtrados + re-renders. **Solución aceptable:** no cambiar nada aquí por ahora, documentar como limitación conocida. El memo de ChannelCard (H5) + virtualización (H1) ya absorben el costo.
